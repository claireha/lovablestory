01 — Overview

What is Lovable?

Build full stack apps & websites through natural-language conversations.

Things I appreciate about Lovable

01 Frontend packages and libraries are already set up
02 Backend can be set up without external accounts
03 Built-in access to AI features without API tokens
04 Quickly deploy and share via a live URL for customer interviews
05 Easily collaborate with others
06 Easier to manipulate for quick changes due to DOM context

02 — Claude

Claude can also prototype.

Claude is usually superior, but:

01 No customer-accessible URL to share for live testing
02 AI-powered prototypes are harder to spin up
03 Without DOM context, prompts need to be more precise

Use Claude when

You need pixel-perfect HubSpot fidelity — Trellis components, real CSS — and you're not sharing it with customers.

03 — Tips

01

Be intentional. Know your goals.

→ Do you want a prototype that customers can access and click through?
→ Does it need to have perfect HubSpot-level fidelity and styling?

02

Learn to get good at both.

→ They are two distinct and powerful tools at your disposal.
→ The more you use both, the more you'll build personal heuristics for when to reach for one over the other.

A lot of it comes down to preference.

The Feature

We shipped screen capture to the Live Chat widget. With one click, visitors on desktop and tablet can take and attach a screenshot directly to their chat conversation — no extensions, no copy-pasting, no asking agents to walk them through it. Less friction for the visitor, more context for the agent.

The Feedback

"This is great. A really useful addition for us. We would love to be able to see the URLs in the screenshot too however. Our URLs can give us a lot of useful information for diagnosing issues (e.g. unique identifiers)."

Bryony Shelton, trykiroku.com

The Problem

The Screen Capture API captures only the tab's rendered content. Not the address bar. Not the browser chrome. This is a hard browser restriction — no web API can access the browser UI.

The Prototype

So I built a quick Lovable app to explore what was actually possible. The idea: capture the tab, then programmatically embed the current URL as an overlay before upload. No browser chrome needed — just the data that matters.

Add a Feature

One prompt.
One change.

Once you have a realistic base, adding a feature is fast. I added a "Route to Agent" step type — described what the panel should show, what options it needed, and what the fallback behavior looked like.

The constraint that matters: one specific thing per prompt. Scope tight. Three things at once gets muddy output — and muddy output slows the conversation you're trying to start.

I showed this to my TL before writing a single line of the spec.

The aha moment

"We caught two edge cases in the first 5 minutes of clicking. Not because we were looking for them — but because clicking a thing surfaces friction that reading about a thing never does."

Dogfood Your Product

Feel the
friction yourself.

The most underrated use: build a customer-facing flow and click through it yourself — as if you're the customer. I built a full chat widget experience. Greeting, branching question, three clickable options. Then I used it.

The mindset shift is everything. You're not designing for a review. You're simulating an experience. Write the prompt from the customer's perspective, not the PM's.

You find friction faster by using a prototype than by reading a spec.

The aha moment

"I caught three things I would never have caught in a doc. The third option in the flow felt wrong the moment I clicked it. No one told me — I just felt it. I knew exactly what to fix."

Before you write your next spec, spend 10 minutes building a prototype.

Lovable isn't a Figma replacement. It's a blank-page replacement. Use it to think out loud — then hand off to design when the direction is clear.
